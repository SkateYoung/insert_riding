# 项目更新日志
## 2026-08-17 取消上下客距离拦截与新增站点运营区范围拦截

### 变更内容

- `POST /fleet/<vehicle_id>/boarding-events` 不再因为车辆当前位置距离目标 O/D 点过远而拒绝上下客确认。
- 请求体中的 `distance_threshold_m` 保留为兼容字段，后端仍会返回 `distance_to_target` 作为诊断信息，但不再作为通过或失败条件。
- `POST /admin/stations` 新增站点时不再校验坐标是否落在所属运营区 SHP 范围内。
- 新增站点仍保留运营区存在性、站点名称、道路/区域、站点方向、经纬度格式和重复坐标等基础校验。

### 兼容说明

- 本次不新增数据库字段或迁移 SQL。
- 历史错误码 `station_coordinate_outside_operation_area`、`operation_area_scope_unavailable`、`too_far_from_stop` 在对应新流程中不再主动返回。

## 2026-08-12 调度成本参数运行时配置

### 变更内容

- 新增 `GET/POST/PUT /admin/dispatch/route-cost-config`，平台可查询和调整插单成本函数参数。
- 支持调整乘客体验、企业效益、社会效益、公平权重，以及候车、在车、晚到、老乘客延误、里程利用率、满载率、社会里程等成本参数。
- `evaluate_route()` 每次评估开始时读取配置快照；接口更新后影响后续新的派单、插单和重规划评估。
- 配置为进程内运行时配置，不主动重算已有车辆路线，服务重启后恢复代码默认值。

### 兼容说明

- 不新增数据库表或迁移 SQL。
- 成本参数字段使用原始大写常量名，便于平台和算法调参文档保持一致。

## 2026-08-12 新增站点方向必填

### 变更内容

- `POST /admin/stations` 新增必填字段 `station_direction`。
- 新增站点时会将 `station_direction` 写入 `map_poi.station_direction`。
- 前端站点管理测试区新增“站点方向”输入框，批量 JSON 示例同步补充该字段。

### 兼容说明

- 不新增数据库字段或迁移 SQL，继续复用已有 `map_poi.station_direction`。
- 该字段会参与 reflect 映射三字段匹配，对应 CSV 中的 `Calc_Dir`。

## 2026-08-12 reflect 站点映射方向匹配

### 变更内容

- `reflect/reflect_station_table.csv` 映射判断从“站点名 + 道路名”升级为“站点名 + 道路名 + 方向”。
- 新规则为 `map_poi.poi_name` 匹配 CSV `STIONNAME`，`map_poi.areas` 匹配 CSV `name`，`map_poi.station_direction` 匹配 CSV `Calc_Dir`。
- 移除 CSV `dist` 字段提取和最小 `dist` 优先选择逻辑；同一个三字段组合出现多条合法记录时，采用 CSV 中第一条合法记录。
- `/pois` 不再返回 `reflect_dist`，新增 `station_direction` 与 `reflect_direction`，用于排查数据库方向与映射表方向是否一致。

### 兼容说明

- 三字段匹配采用严格匹配，方向为空或不一致时不会退回二字段匹配，而是走原始站点坐标最近路网节点吸附。
- 不需要数据库迁移，继续复用 `map_poi.station_direction` 字段。

## 2026-08-11 reflect 站点路网映射

### 变更内容

- 站点加载到算法路网时，优先读取 `reflect/reflect_station_table.csv` 做精确映射。
- 映射规则为 `map_poi.poi_name` 匹配 CSV `STIONNAME`，`map_poi.areas` 匹配 CSV `name`。
- 命中映射后，使用 CSV `gd_lng/gd_lat` 对应的 SHP 路网节点作为 A* 内部站点节点。
- 若映射坐标不在当前路网节点中，则改为按 CSV `gd_lng/gd_lat` 吸附最近路网节点。
- 若映射表不存在、编码无法读取、坐标非法或未命中映射，则自动回退原数据库站点坐标最近路网节点吸附逻辑。
- `/pois` 保持返回数据库原始站点坐标，同时新增 `poi_snap_source`、`reflect_station_name`、`reflect_road_name`、`reflect_lng`、`reflect_lat` 等诊断字段。
- 初始化加载 POI 时会在控制台输出每个站点的映射结果，包含数据库坐标、映射表坐标、最终节点和映射来源。

### 兼容说明

- 不改变 `/order` 请求体和普通订单站点坐标校验规则。
- 不新增数据库字段，`reflect/reflect_station_table.csv` 是本次唯一映射来源。
- 前端继续使用 `/pois` 的 `lon/lat` 发起订单；算法内部使用 `snapped_*` 对应路网节点参与 A*。

## 2026-07-27 车辆管理接口复用通勤快线绑定

### 变更内容

- `PUT /admin/vehicles/<vehicle_id>` 支持根据请求体 `operation_mode` 直接处理通勤快线车辆绑定。
- 当 `operation_mode` 为 `commute_fixed_waiting` 或 `commute_cruising` 时，请求体必须传入 `line_code`；后端会复用 `bus_commute_vehicle_assignment` 写入逻辑。
- 快线模式下车辆所属运营区以 `line_code` 对应线路的 `operation_area_id` 为准，避免前端误传运营区导致车辆和线路不一致。
- 当车辆从快线模式改回 `dynamic_bus` 时，后端会停用该车辆旧的快线绑定关系。
- 响应中新增 `commute_assignment` 和 `commute_runtime_applied`，用于前端确认快线绑定和运行态同步结果。

### 兼容说明

- 原有 `POST /commute/vehicles/assign` 暂时保留，便于旧测试页面继续使用。
- `dynamic_bus` 模式保持原车辆更新逻辑，不要求传 `line_code`。

### 兼容说明

- 本次不新增数据库字段，休息请求来源写入 `bus_driver_rest_request.remark`。
- 删除运营区不会自动取消未完成订单；需要先处理完该运营区订单后再删除。

## 2026-07-21 新增 SHP 文件路径查询接口

### 变更内容

- 新增 `GET /admin/shp-files`，用于查询项目 `shp` 文件夹下可用于运营区配置的 SHP 地图文件路径。
- 接口返回相对于项目根目录的路径，例如 `shp/tianhe_shp_0713/zjgc_0713.shp`，可直接填入运营区 `shp_path`。
- 可用 SHP 判定规则为 `.shp` 文件存在，且同名 `.shx`、`.dbf` 文件同时存在；缺少必要配套文件的数据集不会返回。
- 该接口只扫描本地文件系统，不访问数据库，也不触发运营区加载。

### 验证方式

- `GET /admin/shp-files` 返回 `root`、`count` 和 `paths`。
- `paths` 中的路径统一使用 `/` 分隔，便于前端直接展示和回填。

## 2026-07-20 `/pois` 改为返回数据库原始站点坐标

### 变更内容

- `GET /pois?operation_area_id=xxx` 改为以数据库 `map_poi` 记录为主返回站点。
- 响应中的 `lon/lat` 和 `longitude/latitude` 均为数据库原始站点坐标，前端站点展示、手动下单和随机下单都使用该坐标。
- 运行态内部吸附到路网后的节点坐标保留在 `snapped_node_id`、`snapped_lon`、`snapped_lat` 和 `snapped_node` 字段中，仅作为算法内部地图运算参考。
- 该调整修复了天河测试运营区中 `/pois` 返回吸附节点坐标，导致 `/order` 按数据库站点坐标精确校验失败的问题。

### 兼容说明

- 前端现有随机下单逻辑无需改接口调用，继续从 `/pois` 读取 `lon/lat` 即可得到数据库站点坐标。
- `/map/road-network` 仍返回运行态路网节点，供地图路网展示和算法调试使用。

## 2026-07-20 新增站点校验运营区 SHP 范围

### 变更内容

- `POST /admin/stations` 新增运营区范围校验，站点坐标必须落在所属运营区范围内才会写入 `map_poi`。
- 校验优先使用 `map_operation_area.area_polygon/area_points` 做多边形包含判断；没有面数据时，依次使用已加载路网边界、`bounds_json` 或 SHP 文件 bbox 兜底。
- 新增 `station_coordinate_outside_operation_area` 错误码，用于表示站点坐标不在运营区范围内。
- 新增 `operation_area_scope_unavailable` 错误码，用于表示后端无法取得运营区范围，因而不能完成站点坐标校验。
- 经纬度解析补充有限值校验，避免 `NaN`、`Infinity` 之类非法数值绕过范围判断。

### 兼容说明

- 批量新增仍采用逐项处理模式，某个站点范围校验失败不会影响同批次其他合法站点。
- 如果运营区只有路网线 SHP 且没有面状边界数据，本次兜底校验使用 SHP bbox，只能保证坐标落在该路网外接范围内；如需严格行政边界，应在运营区表补充 `area_polygon` 或 `area_points`。

## 2026-07-18 普通订单改为严格站点坐标校验

### 变更内容

- `POST /order` 不再将任意起终点坐标吸附到最近 POI。
- 下单前按 `operation_area_id + longitude + latitude + deleted=0 + status='enabled'` 精确查询 `map_poi`。
- 起点和终点必须是当前运营区内不同的启用站点，否则订单不会进入调度池。
- 新增经纬度有限值和合法范围校验，并细分站点不存在、坐标歧义、同站起终点、站点未加载及数据库不可用错误。
- A* 继续使用初始化时由数据库站点映射得到的路网节点；高德规划继续使用订单提交的站点原始经纬度。
- `/order` 响应中的 `origin_coords/destination_coords` 改为返回通过校验的原始站点坐标，不再返回道路节点吸附坐标。

### 兼容说明

- 前端随机订单已从 `/pois` 中选择起终点，符合新的严格校验规则。
- 直接构造 `Order` 的内部调用只允许精确命中运行态 POI，或显式传入已经校验的站点路网节点。

## 2026-07-17 通勤快线改为经纬度站点校验并复用 bus_order

### 变更内容

- 通勤快线线路 `stops` 不再要求前端传 `stop_seq`、`station_id` 或 `poi_id`，只传站点经纬度。
- 后端按 `operation_area_id + longitude + latitude + deleted=0 + status='enabled'` 精确匹配 `map_poi`，并把解析出的站点快照保存到 `bus_commute_line.stops_json`。
- 快线订单不再写入独立 `bus_commute_order`，统一复用 `bus_order`，并通过 `order_source='commute_express'` 区分快线业务。
- 快线业务只做车辆匹配和订单状态推进，不再生成 A* 路径、高德驾车路径或车辆导航路线点。
- 快线车辆调用 `/fleet/<vehicle_id>/path` 时只更新 GPS、运行态和位置日志，不触发动态巴士的路网吸附、路线裁剪或上下客联动。
- 该版本曾使用 `anchor_lon/anchor_lat` 表示定点候客锚点；当前模型已在 2026-07-23 移除锚点概念。
- 新增迁移文件 `database/20260717_refactor_commute_express_poi_order.sql`，用于把旧站序折叠到 `stops_json`、迁移旧快线订单到 `bus_order`，并删除旧表。
- `database/bus_dispatch_core.sql` 和 `docs/api接口文档.md` 已同步更新为最终数据模型。

### 注意事项

- 经纬度匹配采用数据库中站点坐标的 8 位小数精确匹配，不做最近点匹配。
- 如果同一运营区同一坐标存在多个启用站点，接口会返回 `commute_stop_coordinate_ambiguous`，需要先清理站点数据。
- 旧迁移中曾出现的 `bus_commute_line_stop`、`bus_commute_order` 已不再作为业务表使用。

## 2026-07-15 远期订单匹配窗口可配置

### 变更内容
